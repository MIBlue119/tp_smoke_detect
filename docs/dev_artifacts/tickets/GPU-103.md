# GPU-103 — Model acquisition, immutable repository, and engine identity

## Result

Implemented the metadata-only R5 model repository and fail-closed acquisition
tooling for the RTX 3090 DeepStream 7.0 profile. The catalog covers
PeopleNet Transformer, MediaPipe Pose Landmarker, MediaPipe Hand Landmarker,
SigLIP 2 crop classification, and the optional LFM2-VL reviewer challenger.
No weights, TensorRT plans, private media, credentials, or remote runtime
fetching were added to Git.

## Contracts and safeguards

- `ml/registry/model_repository.py` validates canonical HTTPS origin, publisher
  revision, license URL/disposition, expected bytes/hash, parent checkpoint,
  dataset/export/SBOM hashes, safe local paths, and immutable rollback target.
- `EngineBinding` requires hashes for the plan, model, export, input contract,
  calibration, build image, and runtime identity (GPU compute capability,
  CUDA, TensorRT, precision, and profile).
- `scripts/verify_model_artifacts.py` is offline by default and emits a
  machine-readable blocked/verified receipt. Acquisition requires both an
  approved complete manifest and explicit `--allow-network`; downloads are
  size/hash checked and atomically promoted.
- `model-repository/manifest/model-release.json` is a real public-source
  metadata catalog with unresolved revision/hash/license/SBOM/rollback fields;
  its receipt is intentionally **blocked** until an approved staging process
  supplies exact evidence.
- LFM2-VL remains disabled and is not treated as a baseline dependency.

## Remaining gate

An ML/release owner must review the five canonical sources, record exact
immutable revisions and byte hashes, approve licenses, register local dataset
and export/calibration receipts, generate/scan SBOMs, build target TensorRT
engines, and set prior-version rollback targets before promotion. The current
blocked receipt is evidence of that missing gate, not a model-quality claim.

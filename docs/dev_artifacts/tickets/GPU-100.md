# GPU-100 — GPU evidence contract

Status: complete on `feature/GPU-100-evidence-contract`

## Scope

U0 freezes the additive, pixels-free `track.candidate.v1` evidence boundary
before GPU media and candidate-consumer work. Existing v1 payloads remain
readable when they omit GPU fields. The related implementation commit is
`0d1c67ca56f49bb0e659674c0b95e77d50260ef1`.

## Delivered

- Added bounded inference roles, statuses, reason codes, deadline outcomes,
  output schemas, model/artifact revisions, request/correlation IDs, and

- Updated the native candidate representation and JSON serializer with the

- Regenerated `schemas/smoke/v1/track.candidate.v1.json`.

## Mixed-version deployment contract

The additive fields are optional for old producers and default to an empty
receipt list and revision map. A strict consumer that has not learned the new
fields must not receive a new producer payload. The GPU bundle rollout order is:

1. Deploy and readiness-check the new strict consumer/core and contract schema.
2. Drain the local broker queue (or replay it through the new consumer) and
   record the queue identity and drain result.
3. Start the native producer that emits receipt fields only after steps 1–2.
4. Roll back in reverse order: stop the new producer, restore the previous
   producer/schema bundle, then restart the previous consumer.

The old-v1 fixture is validated by the updated consumer tests. The native
fixture is validated through JSON parsing and the generated schema. A full
broker rehearsal remains a GPU deployment/integration responsibility for
GPU-104/GPU-109; it is not claimed by this CPU contract unit.

# GPU-108 — GPU observability and degraded-mode integration

Status: **implemented on `feature/GPU-108-observability`**

## Scope

GPU, NVDEC, Triton, queue, sample-loss, model-readiness, restart, deadline,
and fail-closed audio signals are exposed through the existing local metrics
endpoint. Camera identities remain available in the structured readiness
snapshot, but are never Prometheus labels. GPU identifiers, track IDs, event
IDs, URLs, request IDs, and arbitrary provider text are forbidden from metric
schemas; untrusted bounded-dimension values normalize to `other`.

## Delivered

- Aggregated camera freshness, stale count, queue depth, queue age, stream
  state, and scheduled-sample loss metrics without camera labels.
- GPU utilization, memory current/total/high-water/pressure, temperature,
  power, NVDEC utilization, and batch-fill gauges.
- Bounded model readiness, Triton pending requests, inference failures,
  deadline outcomes, component restarts, degraded transitions, and suppressed
  audio counters.
- Prometheus alerts for stale streams, queue pressure, model readiness loss,
  GPU memory pressure, sample loss, inference failures, and restart loops.
- Dashboard panels for camera/queue health, GPU/NVDEC, memory/thermal
  telemetry, Triton readiness, and degraded-mode signals.
- Integration tests cover high-cardinality normalization, GPU overload,
  model timeout, queue saturation, no-audio behavior, per-camera isolation,
  and dashboard/rule surface validation.

# API-102 — API, persistence, and audit

## Scope

Implemented U3's thin FastAPI v1 surface and persistence boundary without
changing the frozen v1 broker contracts or generated schemas.

## Delivered

- `tp_smoke_detect.api.create_app` with liveness/readiness, capabilities,
  camera staging, artifact registration, replay evaluation polling, event
  queries, append-only reviews, site-mode changes, mutes, and model listing.
- Strict Pydantic request models for media type, bounded sizes, modes, review
  labels, and scoped mute validation.
- Artifact path validation rejects absolute paths, URL references, and root
  traversal before persistence.
- Idempotency-Key support for evaluation requests; repeated requests return the
  original evaluation and do not insert another evaluation row.
- SQLite audit repository for the CPU profile with immutable decision/review/
  mode facts, plus PostgreSQL-ready SQL migration under
  `src/tp_smoke_detect/adapters/persistence/migrations/001_initial.sql`.
- Shadow-mode result records `would_announce` while keeping audio eligibility
  false and never creating an audio command.

## Notes / limitations

The initial artifact route registers bounded metadata and a safe relative
artifact reference. Raw media upload and authorization remain deployment-bound
concerns; no private media is stored in this repository. The production
PostgreSQL adapter can implement the same `AuditRepository` protocol using the
checked-in migration and a deployment-selected DB driver.

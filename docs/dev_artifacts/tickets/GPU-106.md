# GPU-106 — Dataset, training, calibration, and sealed evaluation

## Result

Implemented metadata-only U6 tooling for the GPU model combination. Dataset
registration now requires explicit license, provenance, privacy, consent, and
retention dispositions. Grouped manifests expose camera/track/person/capture-
day leakage checks and a stable hard-negative taxonomy. Training calibration is
restricted to non-sealed splits, while sealed ablation reports carry immutable
event-set hashes, Wilson intervals, reviewer resource/provenance gates, and
promotion thresholds.

Added `ml/configs/replay-20-streams.json`, a hashed 20-stream workload manifest
covering codec/profile, 1080p resolution, source/analysis FPS, bitrate/GOP,
occupancy, visible persons, eligible-crop rate, candidate-burst rate, named
confounders, and source status. It is deliberately synthetic metadata-only
until approved external clip hashes are supplied; it cannot certify GPU load.

No datasets, private media, model weights, generated engines, URLs, or
credentials were downloaded or committed.

## Remaining gate

The checked-in replay receipt remains `metadata_only_synthetic`. The ML/release
owner must provide consented local positives and named hard negatives, freeze
camera/time/track/person splits, approve retention/privacy, add real external
clip hashes, and run the sealed event evaluation before any model or GPU
profile can be promoted. Missing model weights produce blocked training
receipts; no fake metrics are generated.

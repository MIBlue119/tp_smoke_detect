# Persistence review remediation: VAL-004, VAL-006, VAL-007, VAL-008

## Scope

Fix metadata retention leakage, shared SQLite concurrency, backup restore
integrity, and audio retry durability without changing the v1 domain/API
contracts.

## Implementation

- Serialized the SQLite repository connection with a reentrant lock, including
  compound transactions.
- Claimed evaluation idempotency keys with one SQLite `ON CONFLICT ... DO
  NOTHING` write and returned the existing record on concurrent retries.
- Added evaluation-to-decision and audio receipt/attempt relationships and
  deleted reviews, evaluations, receipts, and attempt history in the same
  metadata-retention transaction.
- Audio receipt writes now update the latest outcome and append numbered attempt
  records, so accepted playback is visible to cap/cooldown queries.
- Restore now validates exact archive inventory, declared sizes, and SHA-256
  digests in a temporary directory before atomically publishing the destination.

## Verification

- `uv run pytest -q` — 90 passed, 1 skipped (hardware qualification).
- Targeted persistence/audio tests — 11 passed.
- Ruff check/format and mypy for changed runtime files — passed.

## Follow-up

PostgreSQL migration adds `ON DELETE CASCADE` for decisions, evaluations,
receipts, and receipt attempts. Existing SQLite databases receive the nullable
evaluation link through the startup migration; legacy receipt links are
explicitly cleaned during retention because SQLite cannot alter an existing FK
in place.

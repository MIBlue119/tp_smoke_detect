# GPU-101 — GPU stack and host/import qualification

Status: in progress — host-compatible, image import and runtime qualification blocked

## Scope

Freeze and probe the RTX 3090 lab row required by the mandatory GPU release:
Ubuntu 22.04 x86_64, RTX 3090 (compute capability 8.6), R580, DeepStream 7.0
dGPU Triton image, CUDA 12.2, TensorRT 8.6.1.6, and bundled Triton 23.10.

The script is intentionally fail-closed. Host CUDA 12.8 is recorded as a host
capability and is not used as the container runtime identity. GPU-107 remains
the owner of one-stream and 20-stream service qualification.

## Implementation

- Added the digest-pinned `deepstream_triton_rtx3090` image row and explicit
  `gpu_profiles.rtx3090` metadata to `deploy/image-pins.yaml`.
- Added `scripts/qualify_gpu_host.sh`, which captures host, Docker/NVIDIA
  runtime, registry manifest, exact image import, container CUDA visibility,
  DeepStream/Triton command presence, and SBOM evidence.
- The script never changes the driver or OS, mounts no host paths or secrets,
  uses `--network none` for container probes, and returns non-zero unless all
  required evidence is present.
- Added the reproducible receipt at
  `docs/dev_artifacts/qualification/gpu-rtx3090-stack.md`.


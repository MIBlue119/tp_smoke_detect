# OPS-601 — Observability, retention, and degraded modes

## Scope

Implemented U9 on `feature/ops-601-observability-retention`:

- Low-cardinality Prometheus text metrics with an explicit label allow-list;
  track IDs, decision IDs, artifact IDs, URLs, and correlation IDs cannot be
  metric labels.
- Structured JSON logs with context-local correlation IDs.
- Independent component and camera health state, including last good frame,
  queue depth, affected camera count, and last successful activity. A stalled
  camera does not make healthy cameras unready.
- `/metrics` and enriched `/health/ready` API surfaces.
- Separate raw-media, event-clip, and metadata retention clocks. Filesystem
  deletion is path-safe; SQLite marks deletion and writes its audit atomically,
  making missing-file and retry paths idempotent.
- Prometheus scrape configuration, alerts, and a small Grafana dashboard.

## Open integration notes

- Production workers should update `HealthRegistry.record_frame` and
  `set_queue_depth` at their capture boundary.
- A PostgreSQL adapter must preserve the same atomic finalize-and-audit
  transaction semantics as the SQLite reference adapter.
- Prometheus/Grafana deployment is intentionally configuration-only; container
  wiring belongs to INT-701.
